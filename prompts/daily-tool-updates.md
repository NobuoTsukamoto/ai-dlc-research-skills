# AIコーディングエージェント 日次更新

`ai-coding-agent-updates` スキルを使用してください。
日本語の文章表現には `japanese-tech-writing` スキルも使用してください。ただし、簡潔さ、レポートのテンプレート、事実と推論の区別を優先してください。

Asia/Tokyoの `{YYYY-MM-DD}` を対象に、対象ツールのprimary sourceをすべて確認してください。

`collection/candidates.json` がある場合は事前収集結果を使用し、スキルの `references/collection.md` に従ってください。成功したソースの全本文を再取得せず、候補の本文確認と取得失敗の補完に絞ってください。対象日の既存レポートの内容は維持してください。

- 公式アップデートだけを製品事実として扱う
- 新規候補は `update_log.py check` で重複確認する
- 既存収集候補から `references/buzz-and-discovery.md` の条件に合う公式イベントを判別し、製品更新とは別欄に記録する。イベント単独の告知は製品更新ログへ追加しない
- 遅延発見は告知日・変更日と発見日を分けて対象日の日次に記録し、手順に従い該当する作成済み日次・週次・月次も補完する。補完できなければ失敗とし、収集状態を確定しない
- イベントの確認不能と確認できた範囲の該当なしを区別し、候補を判定できない場合もcoverageをpartialとする。既存情報源に限るため網羅的でないことを明記する
- 変更内容は自分の言葉で500文字以内に要約する
- 引用は短い語句（目安40文字以内）に限定し、引用符とcanonical URLを付ける
- 変更内容の要約と実務への影響（推論）を分ける
- 更新なしと確認不能を分ける
- Cursorは公式RSSの`pubDate`をAsia/Tokyoへ変換して対象日を判定し、候補があれば個別Changelog本文を確認する
- AWS Kiroは公式Changelog RSSの`pubDate`をAsia/Tokyoへ変換して対象日を判定し、`link`先のChangelog本文を確認する
- dailyテンプレートでレポートを `updates/daily/{YYYY-MM-DD}.md` に保存する
- 新規の製品更新を `updates/update-log.jsonl` へ追加する

最終回答だけで済ませず、ファイル書き込みツールまたはshellツールで上記2ファイルを実際に作成・更新してください。作業完了前に、指定されたレポートパスとログパスが存在し、レポートが空でないことを確認してください。

`collection/candidates.json` がある場合、全候補のイベント判定と必要な補完を終えた後に限り `collection/event-reconciliation.ok` を作成してください。確認不能の候補は日次に理由を記録してください。レポートへの記録・補完に失敗した場合はこのファイルを作らず、失敗を報告してください。
