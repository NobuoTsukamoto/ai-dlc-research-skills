# AI駆動開発リサーチ方針

## 1. 目的

AI駆動開発に関する研究を継続的に確認し、以下につながる知見を蓄積する。

- チームへのAI開発支援導入
- 社内研修の改善
- 開発プロセスとガイドラインの設計
- 品質、生産性、教育効果の測定
- GitHub Copilot、Claude Code、AGENTS.md、Agent Skills、MCPの活用

## 2. 週間ペース

- 毎週、候補資料を確認する
- 推薦は最大2本
- 精読は原則1本、余力があれば2本
- 新着が弱い週は、過去の重要研究を読む

## 3. 優先テーマ

1. チーム・組織への導入
2. AI利用時の品質、レビュー、テスト
3. コーディングエージェントの能力評価
4. コンテキスト設計、仕様駆動
5. AGENTS.md、Agent Skills、MCP
6. 若手育成、スキル形成、認知負荷
7. 個人のコーディング生産性

## 4. 対象資料

### 優先

- IEEE TSE
- ACM TOSEM
- Empirical Software Engineering
- Automated Software Engineering
- IEEE Software
- ICSE
- FSE
- ASE
- MSR
- CHI、CSCWの関連研究
- DORA
- Microsoft Research
- GitHub Research

### 補助

- arXiv
- Software Engineering Institute
- 大学・研究機関の技術報告
- ベンダー調査

### 原則除外

- 方法やデータが示されない宣伝記事
- 出典を追跡できないまとめ記事
- 実験条件が不明な性能比較
- 同じ研究の重複版
- 単なるツール操作紹介

## 5. 採点基準

| 項目 | 点数 | 判断基準 |
|---|---:|---|
| 関連性 | 0～3 | 現在の業務、チーム導入、研修に直結するか |
| 証拠の強さ | 0～3 | 研究設計、サンプル、比較、再現性が妥当か |
| 適用可能性 | 0～2 | 実務で試せる具体的示唆があるか |
| 新規性 | 0～1 | 既読資料にない知見か |
| アクセス性 | 0～1 | 本文や十分なデータを確認できるか |

7点以上を推薦候補とする。

## 6. 精読の順序

1. Abstract
2. Research Questions
3. Method
4. Threats to Validity
5. 表、グラフ、主要結果
6. Discussion
7. 必要な本文
8. Related Work

## 7. 読後メモ

各資料について、最低限次を記録する。

- 一言要約
- 信頼して採用できる知見
- 条件付きで採用できる知見
- 疑わしい点
- 業務や研修へ適用できること
- 自社で検証したい仮説
- 次に読む資料

## 8. 月次レビュー

月末に以下を統合する。

- 複数研究で一致している知見
- 研究間で矛盾する結果
- エビデンスが弱い一般論
- 実務に導入できるプラクティス
- 自社で試すべき実験
- 研修へ追加すべき内容
- 翌月の優先テーマ
