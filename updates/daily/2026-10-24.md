### GitHub Copilot

#### [Usage metrics API adds usage from tools like OpenCode](https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode)

- 公開日: 2026-10-24
- バージョン / 提供段階: APIメトリクス機能拡張 / stable
- 重要度: medium
- 変更内容（要約）: Copilot使用状況メトリクスAPIにおいて、IDE外部からCopilotをモデルプロバイダとして利用するクライアント（OpenCode、Claude Code、Codex、Zed、Copilot CLI等）の利用量を集計する“totals_by_client”配列が追加された（“reports model usage from more of the tools” (https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode)）。各クライアントごとに成功したモデルリクエスト数、セッション数、プロンプトおよび出力トークン数、モデル別の利用量とモデル選択モードが取得できる。EnterpriseおよびOrganizationの1日・28日レポートが対象となる。
- 制約: Enterprise Owners、Billing Managers、Organization Owners、または「View Copilot Metrics」権限保有者が利用可能。Copilot利用メトリクスポリシーの有効化が必要。クライアント名はリクエスト送信時のインテグレーションIDに基づくベストエフォート判定。
- 実務への影響（推論）: エディタ以外の自律型CLIや外部開発ツールが消費するCopilotモデルの通信量を、サーバー側で横断的に把握できるようになる。ツールごとのトークン消費量や利用頻度を実測値に基づいて比較可能となり、組織内での外部ツール利用規程の策定やモデル予算配分の判断に役立つ。

#### [Turn notifications into code with GitHub Copilot in Teams](https://github.blog/changelog/2026-10-23-turn-notifications-into-code-with-github-copilot-in-teams)

- 公開日: 2026-10-24
- バージョン / 提供段階: Microsoft Teams向けGitHub app更新 / stable
- 重要度: medium
- 変更内容（要約）: Microsoft Teams向けGitHubアプリ（旧称GitHub notifications）が統合され、通知受信とCopilotによる自動修正機能が連携した。チャンネルやチャットに届いたIssue通知に対してメンションを行うことで、エージェントが問題を調査してバグを修正し、プルリクエストを作成するワークフローが導入された（“turn updates into action” (https://github.blog/changelog/2026-10-23-turn-notifications-into-code-with-github-copilot-in-teams)）。従来のレガシー版GitHubアプリは11月16日に廃止予定とアナウンスされている。
- 制約: Microsoft Teams環境およびGitHubアカウントの連携が必要。レガシー版GitHubアプリの利用者は2026年11月16日までに統合版アプリへの移行が必要。
- 実務への影響（推論）: チャットツール上でバグ報告を受け取った直後に、画面を切り替えずに初動調査から修正PRの作成まで指示できるようになる。軽微な不具合や定型的な修正の着手リードタイムが短縮される。一方で、レガシーアプリを利用中の組織は11月16日までにTeamsアプリの再設定とアカウント再接続を進める必要がある。

- 公開日: 2026-10-24
- バージョン / 提供段階: v2.1.310 / stable
- 重要度: medium
- 変更内容（要約）: Claude Code v2.1.310が安定版として公開された。Bedrock、Vertex、Foundry環境において、テレメトリや不要トラフィックが無効な場合でもMonitorツールおよびプラグインモニターが追加された（“Added the Monitor tool and plugin monitors” (https://github.com/anthropics/claude-code/releases/tag/v2.1.310)）。特定ゲートウェイでeffortベータ値や会話途中システムメッセージが拒否された際の再試行、長大コンパクション時のメモリ使用量抑制、Ubuntu AppArmorのuser namespaces制限によるbubblewrap起動失敗時の案内が導入された。またCloud sessionsにEnterpriseカスタムロール向けの権限制御が追加された。
- 制約: 全プラットフォーム対象。Monitorツールは対象クラウド（Bedrock、Vertex、Foundry）環境に適用。Enterpriseロール設定は組織管理者向け。
- 実務への影響（推論）: サードパーティのクラウドプロバイダ経由でClaude Codeを運用するエンタープライズ環境において、監視ツールの稼働や通信ゲートウェイでの失敗が抑止され、接続の安定性が向上する。クラウドセッションの権限が細分化されたことで、セキュリティポリシーに応じた利用権限の統制が容易になる。

### Google Antigravity CLI

#### [Antigravity CLI 1.4.7](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.4.7)

- 公開日: 2026-10-24
- バージョン / 提供段階: 1.4.7 / stable
- 重要度: medium
- 変更内容（要約）: Antigravity CLI 1.4.7が安定版として公開された。フックコマンドが標準入力で受け取るJSONに“lastUserInput”が追加され、エージェント実行前のプロンプト検査が可能になった（“Added lastUserInput to the JSON” (https://github.com/google-antigravity/antigravity-cli/releases/tag/1.4.7)）。Autoモードが定型コマンドで承認を求める頻度を低減させたほか、ヘッドレス実行（-p）時のCPU消費削減、MCPツールのオンデマンド直接返却上限が10KBへ拡大された。またADC認証時のプラグイン読み込み修正や、OAuthトークンのユーザーアカウント分離が施された。
- 制約: 全プラットフォーム対象。lastUserInputはフック有効時に利用可能。OAuthトークン修正に伴い、マルチユーザー環境ではプラグインMCPサーバーへの再サインインが必要な場合がある。
- 実務への影響（推論）: フック機構によるプロンプトの事前検証やポリシー制御が容易になり、企業ルールに沿ったガードレールの構築が支援される。定型処理での承認要求の減少とヘッドレス実行時の負荷軽減により、CI環境やバッチ処理での自動実行が円滑になる。
