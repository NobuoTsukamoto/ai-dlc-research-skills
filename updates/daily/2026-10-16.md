### GitHub Copilot

#### [Upcoming deprecation of selected GitHub Copilot models in mid-November](https://github.blog/changelog/2026-10-15-upcoming-deprecation-of-selected-github-copilot-models-in-mid-november)

- 公開日: 2026-10-16
- バージョン / 提供段階: stable
- 重要度: high
- 変更内容（要約）: GitHub Copilotの全機能（Chat、インライン編集、ask/agentモード、コード補完）を対象に、2026年11月16日をもって特定モデルが提供終了となる予定が告知された（“across all GitHub Copilot experiences” ([canonical URL](https://github.blog/changelog/2026-10-15-upcoming-deprecation-of-selected-github-copilot-models-in-mid-november))）。廃止対象はClaude Opus 4.8、Claude Opus 5、GPT-5.6 Terraの3モデルである。代替としてClaude Opus 5.5、GPT-6.1 Sol、GPT-6 Lunaへの移行が推奨されている。なお、Claude Opus 4.8は年間プランの個人契約者向けには継続提供され廃止対象外となる。Copilot EnterpriseおよびBusinessでは既定で代替モデルが自動有効化されるが、全体ポリシーで無効化している組織は手動許可が必要となる。
- 制約: Copilot全プラン（個人、Pro、Business、Enterprise）が対象。2026年11月16日に廃止予定。年間プランの個人サブスクライバーのみClaude Opus 4.8の継続利用が可能。組織管理者が個別モデルポリシーを設定している場合は事前の許可設定が必要。
- 実務への影響（推論）: 該当モデルを日常業務やカスタムプロンプト、CI連携で明示指定しているチームは、11月中旬までに後継モデル（Claude Opus 5.5やGPT-6系）への切り替えと動作検証を完了させる必要がある。特にOpus 4.8や5でプロンプト挙動を固定化していたワークフローでは、出力品質の差分確認が求められる。組織管理者は管理画面で後継モデルの利用可否ポリシーを点検しておくことが望ましい。

#### [Multi-repository support and other improvements for GitHub in Slack and Teams](https://github.blog/changelog/2026-10-15-copilot-in-slack-and-teams-adds-model-and-repository-updates)

- 公開日: 2026-10-16
- バージョン / 提供段階: stable
- 重要度: medium
- 変更内容（要約）: SlackおよびMicrosoft Teams向けの@GitHubにおいて、同一の対話内で複数リポジトリを横断操作する機能が追加された（“working across multiple repositories” ([canonical URL](https://github.blog/changelog/2026-10-15-copilot-in-slack-and-teams-adds-model-and-repository-updates))）。会話を切り替えることなく、スレッド文脈からの課題作成、フロントエンドとバックエンドにまたがるコード修正やPR作成、リポジトリをまたぐPR状況の確認が可能となった。あわせてメッセージ内の自由な位置での@GitHubメンション対応、リポジトリ切り替えの円滑化、Slackの共有メッセージやスレッド文脈の参照精度向上、エラー低減や中断復帰を含む信頼性の向上が行われた。
- 制約: SlackまたはMicrosoft TeamsのGitHub連携アプリを利用している環境が対象。複数リポジトリへのアクセス権限が必要。
- 実務への影響（推論）: チャットツール上でマイクロサービスや複数コンポーネントにまたがる不具合調査やPR作成を行う際、チャンネルや会話セッションを切り替える手間が省ける。スレッド内の議論ログをそのまま文脈として引き継いでIssueやPRを作成できるため、チャット起点での初動対応やタスク起票の迅速化が期待できる。

### Cursor

#### [Cloud Agent Canvases and Environment Improvements](https://cursor.com/changelog/cloud-agent-canvases-and-environments)

- 公開日: 2026-10-16
- バージョン / 提供段階: stable (Environments API: beta)
- 重要度: high
- 変更内容（要約）: Cursorのクラウドエージェントにおいて、対話作業の一環として対話型キャンバスを作成・共有できる機能が追加された（“build interactive canvases” ([canonical URL](https://cursor.com/changelog/cloud-agent-canvases-and-environments))）。生成されたキャンバスはリンク共有によってチームメンバーと閲覧可能である。また、エージェントが動作するクラウド環境をプログラムから作成・管理できるEnvironments APIがベータ版として提供開始された。さらにクラウドエージェント環境の上限が最大300リポジトリまで拡大され、大規模環境における起動・ロード速度が従来の5倍に高速化された。
- 制約: キャンバス機能および環境改善はCursorのCloud Agent環境が対象。Environments APIはベータ提供。リポジトリ数の上限は最大300件。
- 実務への影響（推論）: クラウド上で自律実行されるエージェントの成果物を、コード差分だけでなく視覚的・対話的なキャンバスとしてチーム内で素早く共有・合意形成できるようになる。さらにEnvironments APIの導入と最大300リポジトリ対応・5倍の高速化により、大規模モノレポやマルチリポジトリ構成を扱うエンタープライズ開発において、エージェント環境の構築自動化と待機時間短縮が進む。
